## 1. 結論（5 行）

1. **C-4: 2〜4 Hz の修正の揺れは、課題の動きよりさらに遠位（肘から先）から来る**: マウスと一緒に動く部分だけで数えると、遠位のシェアは次のとおり（両方とも 400・800 の両方で同じ向き）。
   - slow: 課題の帯域 0.78 → 2〜4 Hz 0.90（+0.12、9/9 人）
   - fast: 0.86 → 0.89（+0.04、8/9 人）
2. **C-4 の中身は方向で違う**:
   - 前後（y）では修正を前腕【参考】が担う（slow で前腕 0.28 → 0.53、上腕・体幹が減る）。
   - 左右（x）では手【参考】が担う（+0.03〜+0.07、8〜9/9 人）。
   - 体幹は修正にほとんど関わらない（2〜4 Hz で −0.10〜+0.01）。
3. **前回（`report_freq.md` §7）の「課題外の動きは近位寄り」は、カメラのノイズによるもので誤りだった**。ノイズ込みのパワーで数えると体幹・上腕が 0.13〜0.33 に見えるが、マウスと相関する部分だけを数えると体幹は約 0 になる。
4. **C-1: 外れる瞬間の多く（65〜89 %）は「置いていかれ」で、そのとき外へずれる動きは上腕から多く出る**:
   - 上腕が課題での役割より +0.15（400）/ +0.21（800）多く、遠位は −0.14 / −0.18 少ない。両 DPI とも 7/9 人、まとめで遠位は 9 人全員が少ない側（p 0.004）。
   - 肘から先は付いていくが、上腕が遅れる。
5. **C-1: 戻すときは遠位が先、近位（体幹 + 上腕）が後**:
   - 戻しのピークは遠位 0.20〜0.29 s、近位 0.29〜0.53 s（差 +89〜+322 ms、全層で同じ向き）。
   - 差は特に前後（y）で大きい（fast で +226 / +269 ms、両 DPI 8/9 人、p 0.008）。
   - 800 では戻しのピーク自体が早い（slow 0.26 → 0.18 s、fast 0.34 → 0.25 s）。

## 2. C-4 2〜4 Hz の修正の揺れはどの関節から来るか

### 2.1 方法

- 2〜4 Hz にはターゲットの成分が無い（課題の最高周波数は 1.075 Hz）ので、この帯域の動きは本人が出した修正・揺れ。
- **マウス（カメラと独立に測った手の動き）とのクロススペクトル**で、各成分のうちマウスと一緒に動いている部分だけを取り出す:
  - B_k = Σ_帯域 CSD(マウス, 成分 k)
  - シェア_k = Re(B_k · conj(B_手先)) / |B_手先|²（和は 1、負 = 手先と逆向き）
- カメラのノイズはマウスと相関しないので、平均すると消える（Welch 4 s 窓、50 % 重なり、1 試行あたり約 19 区間）。
- 比較のため次も出した。
  - 素朴なシェア: ノイズ込みのパワーの割合。前回の方法に近い。
  - coh: 手先（カメラ）とマウスのコヒーレンス。1 = カメラに映る動きがすべて本物。
- 帯域:
  - 課題: 0.2 Hz〜最高の入力周波数
  - 課題外の低い側: 下端〜2 Hz（slow 1.2、fast 1.5）
  - 2〜4 Hz

## 3. C-1 ターゲットから外れた瞬間の前後 1 秒

### 3.1 方法

- **外れた瞬間**: on-target が 1 → 0 になった時刻。
  - 20 ms の中央値フィルタで瞬間的な出入りを除く。
  - 直前に 0.2 s 以上ターゲット内にいたものに限る。
  - 試行の両端 1 s は除く。
- **u** = その瞬間の誤差の向き（ターゲット → カーソル）。すべての速度を u に投影する（+ = 外へ、− = 戻る）。
- **カメラを使わない信号**: 誤差の速度（手の座標）= マウス·u − ターゲット·u / k（k = カーソル mm / 手 mm、試行ごと）。
- **関節**: 各成分の u 向きの速度。カメラの遅れは、試行ごとのカメラ − マウスの遅れ（a0）だけずらして補正した。補正の残りは手先 − マウスで +4〜+41 ms。成分どうしの比較には入らない。
- **役割からのずれ** = 成分の速度 − （完全に追従していたらその成分が出していたはずの速度）。後者はその試行の課題の帯域での分担 × カメラのゲイン × ターゲットの u 向きの速度（`freq_decomp/per_bin.csv` から。x・y は u² で重み付け）。全成分のずれの和 ≈ 手先の誤差の速度。
- **窓**: 基準 [−1.0, −0.6] s、出る前 [−0.3, 0] s、出た後 [0.1, 0.5] s。
- **戻しのピーク**: 出た後 0〜0.8 s で、ずれが最も戻る向きに速い時刻。
- **出方の種類**:
  - 置いていかれ: その瞬間、ターゲットが u と逆向きに動いていた
  - 行き過ぎ: ターゲットは u 向きだが、カーソルがそれより速く外へ出た
- 人ごとに出た瞬間を平均し（1 人 1 条件あたり最少 12〜47 回）、9 人で集計した。

## 5. 限界

- **前腕・手のシェアは手首の点に依存する**（MoCap 未照合）。遠位・近位・上腕・体幹は手首の点を使わない。結論 1・4・5 はこちらで言える。
- C-4 のクロススペクトルの方法は、**マウスと線形に一緒に動く部分**だけを数える。マウスを動かさない体の動き（例えば体幹の揺れを腕が打ち消した場合）は数に入らない。「カーソルの揺れがどの関節から来るか」には正しいが、「体のどこが揺れているか」とは違う。
- C-1 の「役割からのずれ」は、関節が課題の帯域と同じ割合で追従するというモデルを使っている。急な動きのときに分担そのものが変わる場合、ずれの一部はそのモデルの誤差になる。
- C-1 の戻しのピーク時刻は人ごとの平均の曲線から取った。近位は振幅が小さく、ピークの位置がぶれやすい。
- 行き過ぎの外れ方は回数が少ない（層・帯域によって 1 人 3 回未満が 0〜3 人）。
- (層 × 帯域) ごとの FDR では、C-4 の主な結果は q < 0.07 で残るが、C-1 は残らない（q ≥ 0.07）。C-1 は「400 と 800 の両方で同じ向き」を根拠にしている。

## 6. 次に試すとよいこと

1. **手の甲と指に MoCap マーカーを付けて同じ課題をする**: 前腕 vs 手の分担（修正が「肘の伸展」か「手首」か）を確かめる。
2. **外れた瞬間の誤差の向き（x / y）× 出方で、肩・肘の関節角（MoCap）の時系列を見る**: 上腕が遅れるのは肩の屈曲か回旋かを分ける。
3. **ターゲットの急な加速（予測できない成分）を入れた課題**: 「置いていかれ」を意図的に起こし、遠位 → 近位の修正の順序と、上腕の遅れを直接測る。
4. **練度との関係**: 今回は人数が少なく見ていない。熟練者で上腕の遅れが小さいか、修正が遠位に集中しているかを、人数を増やして確かめる。
