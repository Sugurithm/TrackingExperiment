# aim_eval — 上肢の関節協調の解析

`tasks/run_experiment.py` が記録した aim セッション（`recordings/aim_*/`）から、

> 上肢動作は、どこかの関節に依存しているか？全体的に動いているか？
> どこかの関節が一つずつ動いているか？それとも全体が同時に動いて協調し合うことでエイムを合わせているか？

を数値で表し、**プレイヤー内**（センシが変わると関節の動きはどう変わるか）と
**プレイヤー間**（その違いがランダムか、プレイヤーごとの偏りか）を比べる。

## 使い方

`config.py` の `SESSIONS` にセッションを並べる（**ここに書いたものだけが処理される**）。

```python
SESSIONS = [
    dict(dir=r"recordings/aim_Keito400_20261021_170947",  participant="Keito", dpi=400),
    dict(dir=r"recordings/aim_Keito800_20261021_XXXXXX",  participant="Keito", dpi=800),
    dict(dir=r"recordings/aim_Keito1600_20261021_XXXXXX", participant="Keito", dpi=1600),
]
```

```
python aim_eval/run.py --plan            # 対象の確認（試行数・DPI・.db3 の有無）だけ
python aim_eval/run.py --steps joints    # 1. 関節位置の推定（時間がかかる）＋ 確認動画
python aim_eval/run.py --steps video     #    確認動画だけ作る（推定済みの試行から。推定はしない）
python aim_eval/run.py --steps analyze   # 2. 解析（試行ごと → プレイヤー内 → プレイヤー間）
python aim_eval/run.py                   # 1 と 2 を続けて
python aim_eval/verify.py                # 合成データで指標を検証（実データの前に 1 回）
```

- `participant` を揃えれば、フォルダ名がばらばらでも同じ人としてまとまる。
- 記録時に `--dpi` を付け忘れたセッションは `dpi=` に実測値を書けば `counts → cm` の換算も直す
  （`a0` の「手先 / マウス のゲイン」が 1 付近になるかで確認できる）。
- 途中で止めても、再実行すれば終わっている試行は飛ばして続きから進む。

### 推定を速くする（3 つとも入れてある）

1 試行 2790 フレームに Pose（heavy）と Hand を通すと 1 フレーム約 200 ms = **1 本 9.3 分**、
63 試行で 9〜10 時間かかる。速くする手は 3 つ。

| 手 | どこで設定 | 効果 | 注意 |
|---|---|---|---|
| **並列実行** | `aim_eval/config.py` の `JOBS` | PC による（要測定） | 結果は変わらない。メモリ 1 本 1〜2 GB |
| **フレーム間引き** 60→30 fps | `aim_eval/config.py` の `STRIDE = 2` | **ちょうど 2 倍** | 解析結果はほぼ同じ（下記） |
| **Pose を heavy → full** | `experiment/config.py` の `POSE_VARIANT` | 全体で 1.5〜1.7 倍 | **精度が変わる。要確認** |

3 つとも使うと 9〜10 時間が **1.5〜2 時間**程度になる。

**並列数はまず測る**（MediaPipe は 1 本の中でも複数スレッドを使うので、PC によっては効かない）:

```
python aim_eval/bench_joints.py recordings/aim_X_.../trial_01_slow_s1
```

1 本・2 本・4 本並列のスループットを比べて表にする。「1 並列との比」が大きい値を `JOBS` に入れる
（`--jobs 3` でも上書きできる）。1.2 倍に届かなければ `JOBS = 1` のままにする。

**フレーム間引き**は `STRIDE = 2`（既定）。課題の最高周波数は 1.08 Hz、解析前に 5 Hz 低域通過を
かけるので、30 fps（Nyquist 15 Hz）でも情報は落ちない。
同じデータを 60 fps と 30 fps で解析して確かめた結果（差はいずれも誤差）:

| | N_eff | S | C |
|---|---|---|---|
| 60 fps | 3.59 | 0.90 | 1.08 |
| 30 fps | 3.57 | 0.91 | 1.08 |
| 差 | 0.019 | 0.004 | 0.002 |

**Pose モデル**は `experiment/config.py` の `POSE_VARIANT = "heavy"` を `"full"` にする。
`models/pose_landmarker_full.task` を置く必要がある（MediaPipe の公式配布ページから取得）。
heavy で精度検証をしたので、**替える前に必ず 1 試行で差を見ること**:

```
python aim_eval/compare_settings.py recordings/aim_X_.../trial_01_slow_s1
```

heavy/full × stride 1/2 の 4 通りを同じ試行で走らせ、関節位置の差（中央値・95 %）、有効率、
N_eff・S・C、処理時間を表にする。判断のめやす:

- 位置の差が**静止ジッタ（手首 1.9 / 肘 3.1 / 肩 3.8 mm）より小さい**
- N_eff が 0.2 以内、S が 0.03 以内しか動かない
- 有効率が基準より 5 ポイント以上落ちない

この 3 つを満たすなら速い設定に替えてよい。満たさなければ heavy のままにして、
並列と間引きだけで稼ぐ（それでも 4〜5 倍）。

### 1 と 2 は分けて実行する

| 段階 | 1 試行あたり | 1 人ぶん（21 本） |
|---|---|---|
| 関節位置の推定（`--steps joints`） | 9.3 分（既定の設定で 4.7 分） | **1.5〜3 時間**（並列と設定による） |
| 解析（`--steps analyze`） | 約 3 秒 | **1 分** |

推定は MediaPipe を全フレームに通すので長い。解析は 1 分で終わるので、**推定を先に流し、
確認動画を目視したうえで、解析は何度でも回し直す**のが実際の進め方。
`--steps joints` は未処理の試行だけを処理するので、追加で記録したぶんを足すのも同じコマンド。

出力: `analysis/run_log.md`（実行ログ・目視確認用の一覧・点検表）、
`analysis/<参加者>/`（プレイヤー内）、`analysis/between/`（プレイヤー間）、各試行の `eval/`。

## 協調の指標（この研究の核 = a1）

手先（MCP3）の**速度**を、足し算で厳密に 4 成分に分ける:

    手先 = 肩 + (肘 − 肩) + (手首 − 肘) + (MCP3 − 手首)
         = 肩の並進（体幹）+ 上腕の回転（肩関節）+ 前腕の回転（肘関節）+ 手の回転（手首）

3 次元座標だけで決まり（ヤコビアンもモデルも不要）、合計は必ず実際の手先の動きに一致する。

| 指標 | 定義 | 読み方 |
|---|---|---|
| **N_eff** | 1 / Σp²（p = 入力周波数での寄与シェア） | 1 に近い = **どこかの関節に依存**、4 に近い = **全体が動いている** |
| **S** | 入力周波数ごとの N_eff の平均 / 全体の N_eff | 1 に近い = **同時に動く**、1 より小 = **担当が入れ替わる（一つずつ）** |
| **C** | 入力周波数ごとの Σ&#124;成分&#124; / &#124;合計&#124; | 1 = そのまま足し合わさる、>1 = **互いに打ち消しながら手先を作る（協調）** |
| R（補助） | 成分の速さの包絡どうしの平均ペア相関 | + = 同時、− = 交代。**低 DPI のみ有効**（下記） |

仕様の 4 つの問いとの対応: 一関節依存 → N_eff ≈ 1 ／ 全体が動く → N_eff 大 ／
一つずつ → S < 1 ／ 同時に協調 → S ≈ 1 かつ C > 1。
主役の成分（シェア最大）も出すので、「手首型 / 腕型」のような呼び方もできる。

### 検証結果（`verify.py`、20/20 項目 OK）

答えを入れた合成データで 4 つの型を作り、復元できるか確かめている。

| 入れた型 | N_eff（400 → 1600 DPI） | S | C |
|---|---|---|---|
| 手首依存 | 1.46 → 1.42 | 1.00 → 1.02 | 1.00 → 1.01 |
| 全体・同時 | 4.00 → 3.99 | 1.00 → 0.99 | 1.00 → 1.01 |
| 全体・交代 | 3.65 → 3.59 | **0.90 → 0.89** | 1.08 → 1.08 |
| 全体・相殺 | 3.66 → 3.66 | 0.98 → 0.98 | **4.89 → 4.85** |

**N_eff・S・C は DPI を 4 倍にしても変わらない**（最大差 0.06 / 0.01 / 0.04）ので、
1600 DPI も含めて比べられる。あわせて計測系の値（MediaPipe の遅れ +25 ms、
手先 / マウスのゲイン 1.00、人の遅れ +337 ms）も復元できることを確認している。

### 精度について（設計上の要点）

- シェアは **入力周波数のビンだけ**で作り、近傍ビンのノイズを引く。
  ターゲットは 1/T（T = 40 s）の素数倍の正弦波の和なので、信号はそのビンにしか無い。
  時間領域の瞬間シェアで作ると**ジッタが全関節に等しく乗り、一関節依存の動きでも
  N_eff が最大値に張り付く**（合成データで 1.3 → 3.6 になることを確認したので、この方式は採らない）。
- **S の差は 1 割ほど**（交代 0.89 vs 同時 1.00）。1 本では判断せず、同一条件 3 本の平均で読む。
- **R は 1600 DPI で符号まで反転する**。隣り合う成分は同じ関節を共有するので、
  ジッタの包絡が成分間で相関し、必ず「同時」側に偏る。静止試行から偏りを測って引く方法も
  試したが過補正になったため、**動いている成分が 2 つ以上あるときだけ出す**（`R_reliable`）。
  成分が「動いていない」のか「測れていない」のかは、静止試行（`trial_00_static_pre`）から
  測ったノイズ床と比べた時間領域 SNR で判定する。
- 既知の癖（`claude/accuracy_*.md`）: 手首（hand）は振幅 1.00〜1.03 で正確、
  **肘は振幅を 6〜7 % 小さく捉える**、肩は Pose の 2 次元誤差が大きい。
  前腕の寄与は肘の癖のぶん過小になりうる。前腕の回内外は 3 点では求まらない。
- 偏り（皮膚表面と関節中心のずれ、15〜75 mm）は個人内・条件間の比較では差し引かれるので、
  ここでは問題にしない。効くのはばらつきと遅れ。

## プログラムの一覧

### step1 関節位置の推定

| プログラム | 方法 | 出力 |
|---|---|---|
| `step1_joints.py` | **推定**: `config.SESSIONS` の試行を順に見て、`joints/rs_joints.npz` が無いものだけ `experiment/rs_joints.py` を回す。**動画**: npz がある試行すべて（`VIDEO = "all"`）に確認動画を作る。推定を今回したかどうかには依らないので、**すでに推定済みの試行にも後から作れる** | `trial_*/joints/rs_joints.npz`、`trial_*/joints/joints_check_20fps.mp4`、目視確認用の一覧（有効率・最長欠損・左右の取り違え・status の内訳） |

確認動画は `experiment/lib/viz.py` を直接使って **はじめから 20 fps で書き出す**（`VIDEO_FPS`）。
`joints_video.py` は 60 fps 固定なので使わず、**ffmpeg も要らない**。
60 fps の記録から等間隔に間引くので動画は実時間で進み、1 本あたり数 MB に収まる。
画面には関節の点（● = 3 次元座標あり、○ = 深度が取れていない）と、
左上に `3D: NG wrist NO_DEPTH` のような状態、左右を入れ替えたフレームには `L/R SWAPPED` が出る。
一瞬の誤検出は動画では見落としやすいので、**下の一覧（status の内訳・最長欠損）と併せて**確認すること。

有効率が 70 % 未満、または左右の取り違えが 10 % を超えた試行は一覧で警告が出る。
**確認動画を目視して**、座る向き（`config.RIGHT_SHOULDER_IMAGE_SIDE`）や画角を見直すこと。

### step2 プレイヤー内 / プレイヤー間

| プログラム | 方法 | わかること |
|---|---|---|
| `w_within.py` | 1 人の全試行を `trials.csv` にし、DPI × 帯域 × seed で比較。関節ごとの `log(寄与)/log(DPI)` の傾き（**−1 = 必要な分だけ相似に縮める、0 に近い = DPI を上げても動かし続ける**）。同一条件 3 本の SD と「条件間 / 条件内」 | センシが変わると関節の動きがどう変わるか。指標の個人内の安定性 |
| `b_between.py` | 指標ごとに **ICC(1,1)** と判別比 D = SD(人の間)/SD(人の中)、**並べ替え検定**（条件内でプレイヤーのラベルを入れ替えて帰無分布を作る）。参加者プロファイル、(N_eff, S) 平面、クラスタリング、成績との相関 | **ランダムか、プレイヤーごとの偏りか**。偏りがあるとしてどの指標でどれだけ違うか |

判定: **偏りあり** = p < 0.05 かつ D ≥ `MIN_D`（既定 1.5）、**判定保留** = p < 0.05 だが D が小さい、
**ランダム** = 人の違いとして読めない。

## 読むときの注意

- **判別比 D が 1.5 未満の指標で人を分類しない**。D ≒ 1 は「人の違い = 試行ごとのばらつき」と
  同じ意味で、クラスタリングすれば必ず何かの群はできてしまう。
- 参加者が 1 人なら「人によって違う」は言えない。`w_within.py` の ± と「条件間 / 条件内」で
  個人内の再現性を示すところまで。
- 成績との相関は、**指標と成績の両方の D が大きい行だけ**読む。成績が人によって変わらないのに
  相関が大きく出るのは、人数が少ないときの見かけの相関。
- 関節の変位が DPI に反比例するかを見るときは、ジッタの床（`w_within` の σ 列）と比べる。
  1600 DPI の肩の変位はジッタと同程度になりうる。

## 共通の処理（common.py）

- **時刻**: `task.csv` の `epoch` と RealSense のフレーム時刻は同じ PC の時計なのでそのまま対応づける。
  残る遅れ（MediaPipe + 露光）は a0 で測るだけで補正しない。
- **座標**: 机の座標系（x = マウスの右、y = 奥、z = 上）。MoCap がないので、
  マウスの積算変位（真値）に手首の 3 次元変位を回帰して 2 軸を決め、外積で法線を取る。
  手の動きが一番大きい試行で決めた軸を `desk_frame.json` に保存し、その参加者の全試行で使い回す。
- **前処理**: Hampel（9 フレーム、3·MAD）+ 5 Hz ゼロ位相低域通過（`accuracy_eval` と同じ）。
  課題の最高周波数は fast でも 1.08 Hz。
- **FFT**: 解析区間 [0, T) をちょうど 1 周期として 60 Hz の一様グリッドに載せ、窓なしで入力ビンを読む。
