# coord_eval — 上肢の関節協調の解析（統合版）

`aim_eval/`・`skill_analysis/`・`analysis_out/20261022` を作ったスクリプト群（prelim_inference / freq_decomp /
perf_coordination / corrections）で**重複していた読み込み・前処理・寄与の分解・統計を 1 本にまとめ**、
研究の仮説の順に解析を組み直したもの。入力は `recordings/aim_*/` を**読むだけ**で、記録フォルダには何も書かない。

## 使い方

```
python -m coord_eval.verify            # 1. 合成データで指標を検証（初回とコードを変えたとき。約 4 分）
python -m coord_eval.run --plan        # 2. 対象のセッションの確認（参加者名・DPI・試行数）
python -m coord_eval.run               # 3. 解析 → analysis_out/coord/report.md（9 人で数分）
python -m coord_eval.run --no-bias     #    偏りの補正を省く（速い。確認用）
```

- 必要なもの: numpy・scipy・matplotlib（既存の `.venv` と同じ）。リポジトリのルートで実行する。
- 関節位置の推定（MediaPipe）は済んでいる前提（`trial_*/joints/rs_joints.npz`）。推定は従来どおり `aim_eval/run.py --steps joints`。
- 設定は `coord_eval/config.py` だけ。参加者・DPI は `recordings/aim_*` から自動で拾う
  （優先順: config.SESSIONS → `aim_eval_override.json` → フォルダ名 `aim_<名前><DPI>_…` → session.json）。
  記録時の DPI と違えば counts → mm の換算を自動で直す（Yuuki400・Yuya400 は記録時 800 になっている）。
- 群: `GROUPS`（FPS = Kakeru, Suguru, Syou, Xin, Yuya / 非 FPS = Keito, Kosuke, Suzuka, Yuuki）。名前の揺れは `ALIASES`。

**新しく入れたもの**: 1 動作の寄与（H1b）、マウスの向き（H2）、同等性検定と人ごとの判定（H3）、
振幅をそろえた DPI の比較、偏りの補正（擬似データ）、多変量の本人照合、FPS / 非 FPS。

**入れなかったもの**（旧プログラムはそのまま残してあるので必要なら使える）:
- S（同時性）と R（包絡の相関）: S < 1 は方向（x / y）による分担でも生じ、交代の証拠にならなかった。
  R は 800 DPI でほぼ全試行が「信頼できない」になった（`analysis_out/20261022/report.md` §2.2）。
  代わりに周波数の低 / 高でのシェア（補助）と 1 動作の振幅依存を出す。

  優先する 3 つの仮説の外なので移していない。
- `accuracy_eval/`（MoCap を真値にした精度評価）は目的が別（計測系の検証）なので統合していない。
  ここでは「どの指標が【参考】か」の判断にその結果を使っている。

## 仮説と指標

手先（MCP3）= 肩 + (肘 − 肩) + (手首 − 肘) + (MCP3 − 手首) = **体幹 + 上腕 + 前腕 + 手**（足し算で厳密。モデル不要）。
3 成分版は 体幹 + 上腕 + **肘→MCP3**（手首の点を使わない）。

### H1a 全体を通した寄与（「全体の関節移動に対して特定の関節がどれだけ動いているか」）

| 指標 | 定義 | 読み方 |
|---|---|---|
| `gshare_*` 運動量シェア | 成分の変位（3 軸）の入力周波数ビンのパワーから近傍ビンのノイズを引き、和 1 に正規化 | その成分が動いた量の割合（向きは問わない） |
| `eshare_*` 手先への寄与 | 成分の変位をマウスの変位に射影（入力ビン、Re⟨成分, マウス⟩）し和 1 に正規化 | マウスを動かすのにどれだけ効いたか。負 = 逆向きに動いて打ち消す。マウスはカメラと独立なのでカメラのノイズは消える |
| `N_eff` / `N_eff3` | 1 / Σ(運動量シェア)² | 1 = 一関節、4（3）= 全成分が同じだけ |
| `C_glob3` | Σ|成分の振幅| / |手先の振幅|（ノイズを引いた振幅、入力ビン） | 1 = 足し合わさる、> 1 = 打ち消しながら作る |

### H1b 1 動作の中での寄与と協調（「A から B へ動かすとき、どの関節をどう組み合わせるか」）

課題は連続追従なので、**マウス（真値）の速さの谷で区切ったほぼまっすぐな 1 ストローク**を 1 動作とする
（0.2–4 s、正味 8 mm 以上、直線性 0.7 以上。`lib/movements.py`）。始点・終点（±2 フレーム平均）で各成分の変位を測る。

| 指標 | 定義 | 読み方 |
|---|---|---|
| `mshare_*` | 成分の変位の動作方向への射影 / 手先の射影（和 1） | その 1 動作をどの関節で作ったか |
| `N_move` | 成分の変位の大きさ（ノイズ床を引く）から 1/Σq² | **1 動作で実際に動かした関節の数**（前腕だけで足りる動作でも上腕・手首まで動かしていれば大きい） |
| `C_move3` | Σ|成分の変位| / |手先の変位| | 1 = 最小限の動き、> 1 = 手先に出ない動きも使った（冗長） |
| `rslope_prox` | 近位（体幹 + 上腕）の寄与を log2(振幅) に回帰した傾き | 0 = どの大きさの動作も同じ組み合わせ（全体で協調）、+ = 小さい動作は遠位だけ、大きい動作で近位を足す（必要な分だけ動員） |
| 振幅別の表（`amp_profile.csv`）と同じ振幅どうしの 800 − 400（`matched_amp_dpi.csv`） | 振幅の区分 8–16–32–64–128–256 mm | DPI の効果と「動作が小さくなる」効果を分ける |

### H2 マウスの向き（手首 → MCP3）

机の水平面で 手の向き ψ（手首→MCP3）、前腕の向き φ（肘→手首）、手首の水平回転 θ = ψ − φ。

| 指標 | 定義 | 読み方 |
|---|---|---|
| `K_orient` | 1 − dψ/dθ（入力ビンで回帰、θ のノイズを分母から引く） | **0 = 手首を回すとマウスも同じだけ回る**、**1 = 前腕が逆に回り、マウスの向きは一定のまま**、< 0 = 前腕も同じ向きに回る |
| `psi_sdc_per100` | ψ の SD（ノイズ床を引く）/ マウスの変位 RMS × 100 | マウスの向きのぶれの大きさ（動きの大きさで割るので DPI をまたいで比べられる） |
| `psis_sd_per100` | **センサの向き**: 1 s 窓ごとに、マウスが報告する移動方向とカメラの手（palm）の移動方向の 2 次元の回転角。その SD（窓の推定誤差を引く） | **手のランドマークに依らない**「マウスが実際に何度回ったか」 |
| `psis_vs_psi_slope` | センサの向き / 手の向き | 1 = 握りが固い（手の向き = マウスの向き）、< 1 = 指の中でマウスの向きを保っている |
| `psi_per100mm_x`・`psis_per100mm_x` | 向きを手の位置に回帰（左右 100 mm あたり） | 「位置で決まる向き」（弧を描く動き）か「常に一定」か |

### H3 DPI・帯域が変わっても同じ人の協調・寄与は変わらないか

「有意差がない」は「同じ」の証拠にならないので、**同等性検定（TOST）**で「±幅（SESOI）の範囲で同じ」と言えるかを調べる。

- **群レベル**（`invariance.csv`）: 人ごとの差 d（800 − 400 / fast − slow）に TOST と t 検定。主要指標の中で BH 補正。
  判定 = 同等 / 差はあるが小さい / 変化あり / 判定不能。
- **人ごと**（`invariance_person.csv`、report の記号の表）: その人の試行のばらつきから CI を作り判定。
  DPI の比較は**同じ seed = 同じ軌道どうしの対応**をとる（帯域ごとに DPI × seed の表から DPI と seed の効果を除いた残差の SD）。
- **偏りの補正**（`BIAS_CORRECT`）: 400 の試行を 1/2 に縮めて同じセッションの静止試行のノイズを入れ直した擬似 800 で、
  振幅が縮むことだけで生じる指標のずれ（SNR の偏り）を測り、d から引く（`coordination_analysis.md` §6.4 の落とし穴）。
  比・割合の指標だけにかける（mm・deg の指標は縮めた分がそのまま偏りに入るので除く。センサの向きも除く）。
- **個人差の構造**（`individuality.csv`）: 分散を 人・条件・人×条件・試行 に分ける。人×条件 / 試行 ≈ 1 なら
  条件への反応の個人差は試行のばらつき以上には無い。ICC(3,1) = 条件をまたいで人の順序と間隔が保たれるか。
- **多変量の本人照合**（`signature_match.csv`）: 条件 A の各人の指標ベクトルに最も近い条件 B の人が本人か（並べ替え検定）。
- 同等の幅は `config.SESOI`（シェア ±0.05、N_eff ±0.25、C ±0.10、K ±0.15、向き ±2°/100 mm など）。
  **結果を見る前に決める値**。変えるなら理由を書いて報告に載せる。

### FPS vs 非 FPS（`group_tests.csv`）

人の平均（全条件・条件ごと）で並べ替え検定（5 人 vs 4 人は全 126 通り。p の下限 ≈ 0.016）、Hedges g、BH の q。
「DPI での変化量が群で違うか」（不変性が群で違うか）も同じ方法で出す。

## 検証（`verify.py`、合成データ）

`make_synthetic.py` は関節角で動く腕（体幹 2 + 肩・肘・手首の水平回転 3、セグメント長一定）を重み付き逆運動学で動かし、
ノイズ（関節ごとのジッタ 1.8–3.8 mm）・カメラの遅れ 30 ms・ゲイン 0.88・30 fps を入れる。6 人の「型」:

| 名前 | 入れた型 |
|---|---|
| SynWhole | 振幅によらず同じ組み合わせ、手の向きは自由、握りが固い |
| SynForearm | 前腕寄り、手の向きを完全に保つ（κ = 1） |
| SynStab | SynWhole と同じ組み合わせで手の向きを 7 割保つ |
| SynEcon | 大きく遅い動きは肩・体幹、小さく速い動きは前腕・手首（振幅で使い分け） |
| SynShift | 400 は SynWhole、800 では手首を多く使う（DPI で使い方を変える） |
| SynLoose | 手は回るがマウスは 0.3 倍しか回らない（ゆるい握り） |

結果（2026-10-23）: **33 / 33 項目 OK**。ノイズなしの値（真値）に対する試行ごとの誤差は、運動量シェア MAE 0.006–0.011、
N_eff3 0.023、1 動作の近位の寄与 0.015、K 0.048、センサの向き 1.2 deg / 100 mm。
型の検出: K（SynForearm 1.00、SynStab 1.08 vs SynWhole 0.10）、握りの傾き（SynLoose 0.28、SynWhole 0.91）、
振幅依存（SynEcon +0.12 vs SynWhole +0.03）、SynShift の手のシェアが 800 で「変化」・他の 3 人は「同等」。
許容値は結果を見たうえで SESOI の 1/2 程度に置いたもので、厳密な検出力の評価ではない。

**検証で分かった弱点**
- `lag_move_ms`（1 動作の近位→遠位の速度の山の時間差）は真値との相関 0.13。30 fps と 5 Hz の低域通過では 1 動作の中の
  時間差は決まらない。参考値（主要指標にしない）。
- `rslope_prox` は試行ごとの誤差が 0.03 と SESOI（0.05）に近い。人ごとの判定はほぼ「判定不能」になる。人の平均・群で読む。
- 人ごとの判定（1 条件 3 本）はシェアで ±0.05 を言い切るには試行が少ない（判定不能が多い）。
  人ごとに「同じ」と言いたいなら 1 条件 5 本以上が要る。

## 読むときの注意

- 手首・MCP3（MediaPipe Hand）は MoCap での照合が弱い（手首の角度 r = 0.14–0.54）。
  手・前腕の成分、N_eff（4 成分）、ψ・θ・K は【参考】。主結論は 3 成分の指標とセンサの向きで書く。
- 「前腕の回転」は肘→手首ベクトルの動き。肘の屈伸だけでなく肩の回旋で前腕を振る動きも含む（補助の 6 自由度で内訳を見る）。
- 机の座標系は、セッションの全試行でマウスの積算変位に palm の動きを回帰して決める。マウスが大きく回る人
  （センサの向きの SD が大きい人）は回帰のゲインが下がる（report §0 の表で確認）。
- センサの向きの SD は窓ごとの推定誤差を引いているが、実データのノイズが時間的に相関していれば誤差を小さく
  見積もる（ノイズが残る＝高 DPI で大きめに出る）側に偏る。
