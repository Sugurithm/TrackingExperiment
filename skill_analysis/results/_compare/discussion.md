# 考察 — 4 条件の比較（手書き）

> 各条件は独立に解析し（`results/<条件>/`）、ここでは結果を並べて読んだだけです。データは統合していません。
> 数値は 2026-10-23 実行時の `compare.md`・各条件の `data/group_tests.csv` による。1 群 2〜3 人なので、
> 1 条件の p より「**4 条件で同じ向きに出るか**」を重く見ています（偶然なら 4 条件で同じ向きにそろいにくい）。

## 1. どの条件でも見られる特徴（練度に共通する差）

| 特徴 | 400 SLOW | 400 FAST | 800 SLOW | 800 FAST |
|---|---|---|---|---|
| RMS 誤差 A / B / C [mm] | 2.7 / 3.1 / 3.6 | 8.6 / 9.7 / 10.0 | 2.7 / 3.0 / 3.6 | 7.6 / 8.3 / 8.9 |
| on-target A / B / C [%] | 96 / 92 / 86 | 31 / 29 / 25 | 95 / 92 / 87 | 37 / 36 / 30 |
| x（左右）の手首シェア【参考】 A（Syou 除外）/ B / C | 0.16 / 0.19 / 0.12 | 0.19 / 0.28 / 0.13 | 0.36 / 0.38 / 0.19 | 0.43 / 0.49 / 0.22 |

- **追従の正確さ**（RMS・on-target・VAF・線形追従率）と**課題外の速い成分の少なさ**は、4 条件すべてで高練度ほど良い
  （ρ は −0.59〜−0.88、Syou を除いても同じ向き）。練度の分類と成績が整合していることの確認になっている。
- **左右の動きで手首を使う割合**は、4 条件すべてで高練度ほど大きく（ρ +0.44〜+0.79）、肘のシェアはその分だけ小さい。
  **速い入力周波数ほど手首の割合が増える度合い**も 4 条件すべてで高練度ほど大きい（ρ +0.50〜+0.94）。
  → 関節協調で練度と一貫して結びつく唯一の特徴は「**速い・細かい成分を手首に任せる**」こと。
  ただし手首（hand・MCP3）は MoCap で未照合の【参考】なので、計測の確認が要る。

## 2. 特定の条件でだけ見られる特徴

### SLOW だけ: 「小さいうちに直す」修正
- 修正を始めた時点の誤差、ターゲットから外れる頻度、2–10 Hz の揺れは、**SLOW では 400・800 とも**練度差がはっきりある
  （ρ −0.76〜−0.88）が、FAST では差が消える（外れる頻度は FAST で群平均 1.5〜2.0 回/s、on-target は 25〜40 %）。
- FAST はターゲットが速すぎて全員がほぼ常に外れており、「ずれを小さいうちに直す」余地がない。
  **修正の質の差は、追いつける速さの課題でだけ見える特徴**と読める。

### 800 DPI だけ: 高練度ほど多くの関節を使う
- N_eff（関与関節数）は 800 DPI で高練度ほど大きい（SLOW ρ +0.82、FAST +0.69）が、400 DPI では関係がない（+0.06、+0.19）。
- 中身は手首のシェアの増え方の差: 400 → 800 で x の手首シェアが A（除外）0.16 → 0.36、B 0.19 → 0.38 と倍増するのに、
  C は 0.12 → 0.19 しか増えない。**感度が上がった（手の移動量が減った）ときに、高・中練度は手首へ分担を移すが、低練度は肘のまま**。
- 400 DPI では手の移動が大きく、誰でも肘主導になるので差が隠れる、という解釈と整合する。

### 400 DPI だけ: 肩と肘が独立に動く
- Syou を除くと、400 DPI では肩–肘の速度相関が高練度ほど低い（SLOW ρ −0.94、FAST −0.76）が、800 DPI では関係がない（+0.36、−0.13）。
- 「肩と肘が逆向きの割合」は **条件で向きが逆**（400 では高練度ほど大きい、800 では高練度ほど小さい）。
  → 肩–肘の関係は練度の安定した特徴とは言えない。手の移動が大きい 400 DPI でだけ現れる現象として扱うのが安全。

## 3. どの条件でも見られない特徴

- **滑らかさ（躍度比・LDLJ）**: 条件によって向きが変わり（躍度比 ρ −0.31〜+0.50）、練度との関係は見えない。
  練度差は躍度ではなく「課題外の帯域のパワー」に出る（上の 1）。
- **実効遅れ（位相の傾き）**: どの条件でも |ρ| ≤ 0.34。周波数ごとの位相遅れの平均は 400 SLOW でだけ差がある。
- **相殺比 C・周波数間の分担のそろい S・肩関節や遠位のシェア**: どの条件でも一貫した関係がない。
  **分担の基本の型（肘主導、左右 = 肘、前後 = 肩関節）は練度によらず共通**。

## 3.5 どの関節から動かすか（動き出しの順序）

手先（MCP3）が向きを変える瞬間（1 試行あたり SLOW 約 70 回、FAST 約 150 回）に、各成分が同じ向きに切り返した時刻の差 τ を測った
（`initiation.py`。負 = 手先より先）。群平均 τ [ms]（A は Syou 除外）:

| 成分 | 400 SLOW A / B / C | 400 FAST | 800 SLOW | 800 FAST |
|---|---|---|---|---|
| 手首【参考】 | −23 / −25 / −15 | −26 / −22 / −19 | −24 / −16 / −12 | −26 / −18 / −17 |
| 肘 | −16 / −8 / −11 | −7 / +1 / −9 | +13 / +7 / +1 | +20 / +10 / −1 |
| 肩関節 | +23 / −2 / +2 | +29 / +20 / +22 | −17 / +16 / +1 | +10 / +26 / +13 |
| 体幹 | +38 / +49 / +77 | +26 / +28 / +104 | +40 / +8 / +39 | +37 / +35 / +76 |
| 肘 − 手首 | +15 / +37 / +8 | +38 / +40 / +19 | +45 / +51 / +23 | +67 / +54 / +29 |

- **全員に共通**: 平均すると 手首 → 肘 → 肩 → 体幹 の順（遠位から）に切り返す。ただし「最初に動く成分」はイベントごとにばらばらで
  （手首 24〜38 %、肘 24〜28 %、肩 22〜27 %、体幹 12〜25 %）、**決まった関節から必ず動き出すわけではない**。
  手首（Hand モデル）と肩・肘（Pose モデル）は推定モデルが違うので、「手首が先」という絶対的な順序は割り引いて読むこと。
- **肩と肘のどちらから動き出すか**: 練度差なし。ρ の向きが条件で入れ替わる（「肩が肘より先の割合」ρ −0.50〜+0.57）。
- **練度差がありそうなのは手首と肘の間隔**: 高練度ほど**手首が先に切り返し、肘がそれより遅れて付いてくる**
  （肘 − 手首の時刻差 A 15〜67 ms vs C 8〜29 ms）。ρ は 8 列（4 条件 × 全員 / Syou 除外）すべて同じ向き（+0.25〜+0.82）で、
  手首の τ も 8 列すべて負の向き（高練度ほど早い）。低練度は手首と肘がほぼ同時に（一体で）切り返す。
  連続追従中の位相（`lead_*_ms`）でも 8 列すべて同じ向き（高練度ほど手首が相対的に早く、肘・肩が遅い）なので、2 つの方法で整合する。
  → 1 の「速い・細かい成分を手首に任せる」と同じ構図で、**高練度は手首で先に向きを変え、肘は後から大きく運ぶ**分業をしている可能性。
- 体幹の切り返しは低練度ほど遅れる（C 39〜104 ms、8 列すべて同じ向き）。体幹はほとんどの人で寄与が小さいので、
  腕に引きずられて遅れて動く受動的な揺れと読むのが自然。
- 注意: 判別比 D は多くが 1 未満（SLOW）〜2 程度（800 FAST）で、1 条件だけでは人の違いが試行のばらつきと区別できない。
  差の大きさ（10〜40 ms）も RealSense のフレーム間隔（33 ms）と同程度（0 交差は補間で 1 フレーム未満まで求めている）。
  **言えるのは「4 条件で向きがそろう傾向」まで**。

## 4. Syou

- **4 条件すべてで体幹（肩の並進）のシェアが突出**（ロバスト z = +73 / +19 / +35 / +18）。サブムーブメントの多さ・LDLJ の低さ（ぎくしゃく）も
  3 条件で外れている。一方、成績は 4 条件とも A〜B 群の範囲内。
- → Syou は条件によらない一貫した「肩ごと動かす」スタイルで、**成績の外れ値ではなく動かし方の外れ値**。
  成績の結論は Syou の有無で変わらない。協調の結論は Syou を含めると薄まるものがある（体幹シェア、手首の周波数変化など）ので、両方を併記する。

## 5. B 群（中練度）について

4 条件すべてで **Kakeru は A 並み**（800 FAST では on-target 43 % で全員中 1 位）、**Xin は C 並み**の成績。
B を 1 つの群として扱うと平均が A と C の中間になるのは、2 人の平均だから、という面が大きい。
練度の定義（自己申告・ゲーム歴など）と成績の対応を見直す価値がある。

## 6. 次に確かめるとよいこと

1. **手首シェアの計測確認**: 唯一一貫した協調の特徴が【参考】の成分なので、手首の推定精度（MoCap 照合、または手の向きが取れる点の追加）を確かめる。
2. **DPI × 練度の交互作用**: 「800 DPI で手首へ移す」のは個人内の変化なので、参加者ごとに 400 → 800 の変化量を練度と比べる
   （各条件の `data/persons.csv` の `share_x_hand` を参加者で突き合わせればよい）。
3. Syou の肩の並進が姿勢推定の誤差でないことを確認動画で目視する（`recordings/aim_Syou*/trial_*/joints/joints_check_20fps.mp4`）。
